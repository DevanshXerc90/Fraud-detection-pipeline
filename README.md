# Credit Card Fraud Detection Pipeline

An end-to-end, reproducible fraud-scoring project using the Kaggle/ULB
Credit Card Fraud Detection dataset. It trains three models, selects one by
five-fold cross-validation average precision, tunes its threshold on validation
data, saves compatible inference artifacts, and
serves scores through FastAPI.

This is an offline portfolio experiment, not a production-ready fraud system.
The dataset contains 284,807 anonymized transactions from 2013, covering
approximately two days, with 492 frauds (0.172%). Its currency and business
context are unspecified.

## Setup

```bash
git clone https://github.com/DevanshXerc90/Fraud-detection-pipeline.git
cd Fraud-detection-pipeline
pip install -r requirements.txt
```

Download `creditcard.csv` from the [Kaggle dataset](https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud)
and place it at `data/creditcard.csv`. The dataset is intentionally not
committed. Training and evaluation are reproducible with:

```bash
python train.py
```

The run uses seed 42 and a stratified 70%/10%/20% train/validation/test split.
Feature engineering and preprocessing are fitted on training data only.
Five-fold stratified cross-validation is also run on the training partition;
each fold fits its own feature engineer and preprocessor. The held-out test
partition is evaluated once after model and threshold selection.

## Pipeline

```text
creditcard.csv
  -> stratified split
  -> fitted FeatureEngineer
  -> fitted RobustScaler preprocessor
  -> Logistic Regression / Random Forest / XGBoost
  -> CV model selection and validation-only F1 threshold
  -> held-out test metrics and bootstrap intervals
  -> model.pkl + feature_engineer.pkl + preprocessor.pkl + metadata.json
  -> FastAPI
```

The `Time` column is elapsed seconds from the first transaction. The feature
engineer creates: `LogAmount=log1p(Amount)`; `HourOfDay=floor(Time/3600) mod
24`; circular `HourSin`/`HourCos`; an elapsed-time `IsNightTime` bucket;
`V14_x_V17`; PCA-vector magnitude; `IsMicroTx` for `Amount <= 1.0`;
`AmountPercentile` against the fitted training amount distribution; and
`TimeSinceFirstTxNorm` using fitted training time bounds. The last two use
training reference statistics, so inference does not re-rank the request
batch. `IsMicroTx` is not evidence of card testing, and SHAP associations are
not causal explanations.

## Models and verified results

The bundled `models/results.json` was generated by the current training run.
The saved model is selected by the highest mean AUPRC across identical
five-fold stratified folds on the training partition. XGBoost and Random
Forest are close (`0.8582` vs `0.8543`); this rule is reproducible and is not
a claim that XGBoost is statistically superior:

| Model | Validation AUPRC | Five-fold mean AUPRC (std) |
|---|---:|---:|
| Logistic Regression | 0.6799 | 0.7666 (0.0414) |
| Random Forest | 0.7894 | 0.8543 (0.0587) |
| **XGBoost** | **0.8040** | **0.8582 (0.0643)** |

The selected model's threshold is tuned on validation data only and is
`0.937918`. On the untouched 56,962-row
stratified test set (98 frauds; 0.1720% prevalence):

| Metric | Value | 95% bootstrap percentile interval |
|---|---:|---:|
| AUPRC | 0.8812 | 0.8151–0.9360 |
| Precision at selected threshold | 0.9405 | 0.8817–0.9873 |
| Recall at selected threshold | 0.8061 | 0.7253–0.8766 |
| F1 | 0.8681 | — |
| ROC AUC | 0.9788 | — |

The selected threshold confusion matrix is `[[56859, 5], [19, 79]]`:
TN=56,859, FP=5, FN=19, and TP=79. `results.json` also reports precision,
recall, F1, and confusion matrices at the selected threshold, `0.5`, values
0.05 below/above the selected value, and the validation threshold targeting
approximately 90% recall. The actual results are reported; no test labels
were used to choose these thresholds.

Intervals use 1,000 fixed-seed bootstrap resamples of test examples and the
2.5th/97.5th percentiles. Replicates without a positive example are skipped;
none were skipped in this run. These metrics describe this offline dataset,
not expected future or production performance.

The separate chronological experiment sorts by elapsed `Time`, uses earlier
70% for training, the next 10% for validation, and the later 20% for testing.
It selected XGBoost on validation AUPRC 0.8436 and measured later-period test
AUPRC 0.7983, precision 0.9464, and recall 0.7067 at its validation threshold.
The split contains 199,364/384, 28,481/33, and 56,962/75
rows/frauds for train/validation/test. Its bootstrap intervals are stored in
`models/results.json`; replicates without positives are skipped and reported.
These intervals measure test-sample uncertainty, not all uncertainty from
model or threshold selection. Random and chronological metrics are not
identical-distribution comparisons.

LightGBM was removed from the active pipeline. Reproduction on the original
split used continuous positive-class scores correctly but produced validation
AUPRC 0.0430, so it is not retained merely to claim four models.

The dataset contains 1,854 rows belonging to 773 exact duplicate groups
(1,081 duplicate occurrences beyond each group's first row). The stratified
split has 150/271/56 duplicate row hashes crossing train-validation,
train-test, and validation-test boundaries. The chronological split has no
cross-boundary duplicate hashes. Duplicates were retained because repeated
transactions may be legitimate events; they are reported rather than silently
dropped. See `duplicate_audit` in `models/results.json`.

## Scores and API

The API returns an uncalibrated positive-class **model score**, not a
calibrated probability. Class weighting and `scale_pos_weight` make probability
interpretation unjustified without a separate calibration study.

```bash
uvicorn src.api.main:app --host 0.0.0.0 --port 8000
```

Endpoints:

| Method | Path | Purpose |
|---|---|---|
| GET | `/health` | Readiness and artifact status |
| POST | `/predict` | Score one transaction |
| POST | `/predict/batch` | Score a bounded batch |
| GET | `/docs` | Swagger UI |

Risk bands are display labels: LOW `<0.4`, MEDIUM `0.4–<0.7`, HIGH
`0.7–<0.9`, and CRITICAL `>=0.9`. The binary `is_fraud` decision uses the
validation-selected threshold `0.937918`; therefore a score such as `0.92`
can be HIGH but not `is_fraud`, intentionally communicating display severity
separately from the operating decision. Boundary behavior is covered by API
tests.

## Artifacts, tests, and Docker

Training writes compatible artifacts to `models/`: `model.pkl`,
`preprocessor.pkl`, `feature_engineer.pkl`, `metadata.json`, and
`results.json`. Metadata records the selected model, threshold, feature schema,
seed, evaluation date, Git revision, cross-validation, and temporal results.
For XGBoost, `model.xgb.json` is also written in XGBoost's native JSON format;
the joblib artifact remains the API compatibility artifact. Pickle/joblib
artifacts must only be loaded from trusted sources.

Training logs one MLflow run per model under the local MLflow tracking
directory. This is implemented in `src/models/trainer.py`, is not a remote
service, and has no claimed screenshot. Run `python train.py` to create runs.

```bash
pytest tests/ -v
python -m compileall -q src train.py
docker compose up --build
```

The image contains model artifacts but not the local dataset. Compose checks
`/health`; serving predictions does not require `data/creditcard.csv` once
artifacts exist. Local latency measurements, if performed, describe only the
specified machine and warm-up procedure; they are not production throughput.

## Limitations

The data is historical, anonymized PCA data with very few positive examples
and no specified currency or operational costs. Offline random and temporal
metrics have uncertainty and cannot establish future performance, calibration,
fairness, drift behavior, or production readiness. Deployment to Render and
external production validation are not part of this repository verification.
